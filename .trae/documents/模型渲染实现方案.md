# 模型渲染实现方案

## Context（为什么要做）

当前 `TestRender` 只把 ImGui 画上屏，模型完全没渲染：

- [初始化函数](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L30-L76) 里 8/9/10/11/12/13/15/16/19/20 号步骤全被注释掉，选中区间那个"每模型"循环体是空的。
- [渲染函数](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L78-L149) 只调用 ImGui，没有绑管线 / 发 draw。
- 渲染通道是**纯 ImGui 版**（[第 335 行注释](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L335)）：单颜色附件、无深度、无 MSAA。
- 没有任何"每个 SubMesh 一份 GPU 资源"的存储。

目标：把 `GUI_Model::models` 里的模型按各自材质真正渲染出来；**材质的 shader 为空（未通过"应用"按钮赋过材质）时跳过该 SubMesh**。

已确认的关键事实：

- 顶点真实类型是 [Other1::Vertex](file:///\\legion\共享文件夹\VulkanTest/Header/Other.h#L110-L126)（`tangents` 是 vec3，与 [填充模型数据](file:///\\legion\共享文件夹\VulkanTest/Test/GUI_Model.cpp#L130-L162) 的写法一致）；`TestRender::Vertex`（vec4 版）是半成品，本方案不使用。
- 模型导入**不填材质** → 导入后 `material.shader` 为空，恰好是"跳过"的情形。
- [读取顶点输入数据](file:///\\legion\共享文件夹\VulkanTest/Test/GUI_ShaderSystem.cpp#L387-L465) 已接进 [读取顶点和片段着色器](file:///\\legion\共享文件夹\VulkanTest/Test/GUI_ShaderSystem.cpp#L471-L484)，`Shader::inputDescriptions` 里是 `{location, format, offset}`，可直接生成 `VkVertexInputAttributeDescription`。
- DXC 编译时带了 `-fspv-entrypoint-name=main`，管线 `pName` 固定填 `"main"`。
- 已有可复用工具：`创建Buffer` / `复制Buffer` / `创建临时命令缓冲` / `结束临时命令缓冲`（[TestRender.cpp](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L1107-L1195)）、`创建VkImage_12` / `创建图像视图_12`、[创建贴图采样器_10](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L419-L447)。

## 设计决策（已与用户确认）

1. **深度 + MSAA 一起加**：改造渲染通道与帧缓冲，启用已写好的 `创建MSAA颜色附件_12` / `创建深度附件_13`。
2. **GPU 资源存进 `Other1::SubMesh`**：直接给 `SubMesh` 加 Vulkan 句柄字段。
3. **相机 view/projection 走 UBO，model 矩阵走 push constant**。

## 实施步骤

### 1. 数据结构扩展

[Header/Other.h](file:///\\legion\共享文件夹\VulkanTest/Header/Other.h#L128-L134) —— `SubMesh` 增加 GPU 字段（用裸句柄，避免引入 `TestRender::GpuBuffer`）：

```cpp
// GPU 资源（由 TestRender 创建、销毁）
VkBuffer       vertexBuffer       = VK_NULL_HANDLE;
VkDeviceMemory vertexBufferMemory = VK_NULL_HANDLE;
VkBuffer       indexBuffer        = VK_NULL_HANDLE;
VkDeviceMemory indexBufferMemory  = VK_NULL_HANDLE;
uint32_t       indexCount         = 0;
VkPipeline     pipeline           = VK_NULL_HANDLE;   // 空 shader 时保持 VK_NULL_HANDLE，渲染时据此跳过
glm::mat4      modelMatrix        = glm::mat4(1.0f);  // 走 push constant
```

[Test/TestRender.h](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.h#L95-L142)：

- 新增 `Other1::Camera camera;`（被 Hierarchy 面板驱动，供 UBO 使用）。
- 新增 `std::vector<VkDescriptorSet> cameraDescriptorSets;`（每在途帧一个，所有 SubMesh 共用）。
- 新增私有方法声明：`创建着色器模块`、`创建材质管线`、`创建相机描述符集`、`更新相机Uniform`、`选定采样数_7_3`。
- `FrameResources` 增加 `VkDescriptorSet cameraDescriptorSet`（或直接复用上面的 vector）。

相机传递链：`TestRender::camera` → `Test_ImguiVulaknBackend` 新增 `Other1::Camera& camera` 成员 → [GUI_Hierarchy](file:///\\legion\共享文件夹\VulkanTest/Test/GUI_Hierarchy.h#L15) 的 `camera` 由值成员改为引用，面板改动直接写回 `TestRender::camera`。（沿用本项目已踩过的"必须用引用"教训。）

### 2. 渲染通道 + 深度 + MSAA

[创建渲染通道_7](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L333-L380) 重写为 3 个附件：

- 附件 0：MSAA 颜色（`samples = sampleCount`，`loadOp = CLEAR`，`storeOp = DONT_CARE`，`initialLayout = UNDEFINED`，`finalLayout = COLOR_ATTACHMENT_OPTIMAL`）
- 附件 1：深度（`samples = sampleCount`，`loadOp = CLEAR`，`storeOp = DONT_CARE`，格式用 [选定深度格式7_1](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L988)）
- 附件 2：解析目标（交换链图像，`samples = 1`，`loadOp = DONT_CARE`，`storeOp = STORE`，`initialLayout = UNDEFINED`，`finalLayout = PRESENT_SRC_KHR`）

子通道：`pColorAttachments = &msaaRef`，`pResolveAttachments = &resolveRef`，`pDepthStencilAttachment = &depthRef`。依赖改覆盖 `COLOR_ATTACHMENT_OUTPUT` + `EARLY_FRAGMENT_TESTS/LATE_FRAGMENT_TESTS`。

[创建帧缓冲_14](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L668-L692)：附件数组改为 `{ msaaImage.view, depthImage.view, swapchain.imageViews[i] }`（顺序必须与附件下标一致）。

`sampleCount` 目前恒为 `VK_SAMPLE_COUNT_1_BIT` 且从未赋值 —— 新增 `选定采样数_7_3()`：查 `VkPhysicalDeviceProperties.limits.framebufferColorSampleCounts & framebufferDepthSampleCounts`，取 4x 或退到 1x，在 `初始化函数` 里于创建渲染通道**之前**调用。

`初始化函数` 中**取消注释**：`创建MSAA颜色附件_12()`、`创建深度附件_13()`，顺序放在 `创建渲染通道_7()` 前后皆可（两者只建图像，不依赖渲染通道），但必须在 `创建帧缓冲_14()` 之前。

[渲染函数](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L100-L112) 的清屏值改为 2 个（颜色 + 深度），`clearValueCount` 置 3（解析附件下标为 2，即便不 clear 也要占位）。

ImGui 后端无需改动：`initInfo.PipelineInfoMain.MSAASamples` 已传 `sampleCount`，`RenderPass` 已传 `renderPass`。

### 3. 管线与 GPU 资源（在"每模型"循环里）

改 [初始化函数](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L44-L57) 的循环：`auto model` → `auto& model`（当前是**值拷贝**，改不到真数据），循环体内对每个 `mesh`：

```cpp
const Other1::Shader& shader = mesh.material.shader;
if (shader.spvVert.empty() || shader.spvFrag.empty()) continue;   // ← shader 为空则跳过
```

然后依次：

- **上传顶点/索引缓冲**：参照 [上传顶点缓冲_15](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L694-L724) 的暂存缓冲套路，改成带参数版本（传 `mesh.vertices` / `mesh.indices`），`bufferSize = vertices.size() * sizeof(Other1::Vertex)`，写入 `mesh.vertexBuffer`；索引同理，并记录 `mesh.indexCount`。原两个无参函数可以保留为薄封装或直接替换。
- **创建着色器模块**：新增 `创建着色器模块(const std::vector<char>& spv) -> VkShaderModule`，`pCode = spv.data()`、`codeSize = spv.size()`。
- **创建材质管线**：新增 `创建材质管线(SubMesh&)`，包含：
  - 顶点输入：binding 0，`stride = sizeof(Other1::Vertex)`，`VK_VERTEX_INPUT_RATE_VERTEX`；属性数组**直接由 `shader.inputDescriptions` 生成**（`location/format/offset` 原样填入，`binding = 0`）。
  - 光栅化/深度/混合状态**读 `mesh.material.state`**（`RenderState`）：`cullMode`/`frontFace`、`depthTestEnable`/`depthWriteEnable`/`depthCompareOp`、`blendEnable` + 各 blend 因子/op。模板暂保持关闭（`stencilTestEnable` 先忽略）。
  - 管线布局：复用共享的 `descriptorSetLayout` + 一个 `VkPushConstantRange{VK_SHADER_STAGE_VERTEX_BIT, 0, sizeof(glm::mat4)}`。管线布局可全局只建一个。
  - `pName = "main"`，`renderPass`/`subpass = 0`，`rasterizationSamples = sampleCount`。
- **描述符池/相机描述符集**：`初始化函数` 里取消注释并调用 `创建描述符池_19()`，实现并调用 `分配相机描述符集_20()` —— 每在途帧一个 set（`setLayout = descriptorSetLayout`），只写 binding 0（相机 UBO，`VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`）。binding 1（贴图）**暂不写**：当前 `PSMain` 返回纯白、不使用 `albedoTexture`，DXC 会把它优化掉，着色器不会访问 binding 1，留着不写是合法的。

> 说明：项目里目前**没有任何贴图加载代码**（无 stb_image、无 Assimp 内嵌纹理解析）。等以后要真正采样贴图时，再补一个 1×1 白色占位纹理并写 binding 1 即可，本次不做。

### 4. 相机 UBO

新增 `更新相机Uniform()`：由 `camera.transform.position`（+ 目标点/上方向）算 `glm::lookAt` 得 view，由 `camera.fov`/`nearPlane`/`farPlane` 与 `swapchain.extent` 宽高比算 `glm::perspective` 得 projection，**`proj[1][1] *= -1.0f`**（Vulkan 的 Y 轴与 GL 相反），写进 `frame.uniformBufferMapped`。

在 [渲染函数](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L78) 开头（`vkWaitForFences` 之后、录制命令前）调用一次。

### 5. 渲染循环里的绘制

在 [渲染函数](file:///\\legion\共享文件夹\VulkanTest/Test/TestRender.cpp#L112-L115) 的 `vkCmdBeginRenderPass` 之后、`ImGui_ImplVulkan_RenderDrawData` **之前**插入：

```cpp
vkCmdBindDescriptorSets(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, pipelineLayout, 0, 1,
                        &frames[currentFrame].cameraDescriptorSet, 0, nullptr);

for (auto& model : GUI.modelGUI.models)
    for (auto& mesh : model.subMesh)
    {
        if (mesh.pipeline == VK_NULL_HANDLE) continue;   // ← shader 为空 / 未建管线则跳过
        vkCmdBindPipeline(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, mesh.pipeline);
        vkCmdPushConstants(cmd, pipelineLayout, VK_SHADER_STAGE_VERTEX_BIT, 0,
                           sizeof(glm::mat4), &mesh.modelMatrix);
        VkDeviceSize offset = 0;
        vkCmdBindVertexBuffers(cmd, 0, 1, &mesh.vertexBuffer, &offset);
        vkCmdBindIndexBuffer(cmd, mesh.indexBuffer, 0, VK_INDEX_TYPE_UINT32);
        vkCmdDrawIndexed(cmd, mesh.indexCount, 1, 0, 0, 0);
    }
```

视口/裁剪是动态状态，若管线未静态指定需补 `vkCmdSetViewport` / `vkCmdSetScissor`（当前 `创建图形管线_11` 里是静态指定，新管线建议沿用静态指定，或用 `VK_DYNAMIC_STATE_*` + 每帧设置）。

### 6. 着色器改造成使用矩阵

[shaders/TestShader.shader](file:///\\legion\共享文件夹\VulkanTest/shaders/TestShader.shader#L59-L71) 的 `VSMain` 目前直接 `output.position = float4(input.position, 1.0)`，不含任何矩阵 → 即使管线正确也看不到模型。需补充：

```hlsl
cbuffer CameraUBO : register(b0, space0) { float4x4 view; float4x4 projection; };
[[vk::push_constant]] cbuffer PushConstants { float4x4 model; };
...
output.position = mul(projection, mul(view, mul(model, float4(input.position, 1.0))));
```

> 注意：该文件里 `[[vk::location(n)]]` 当前是**手写**的（[第 35-43 行](file:///\\legion\共享文件夹\VulkanTest/shaders/TestShader.shader#L35-L43)）。导入时 [修改顶点输入名称](file:///\\legion\共享文件夹\VulkanTest/Test/GUI_ShaderSystem.cpp#L274) 会再插一层，导致双重注解编译失败 —— 需要先把文件里手写的那份删掉，或给该函数加"行内已含 `[[vk::location` 就跳过"的判断。此项需一并处理。

### 7. 清理

`清理函数` 目前是空的。至少补：逐 SubMesh `vkDestroyBuffer` + `vkFreeMemory` + `vkDestroyPipeline`。完整清理（管线布局、描述符池、图像、交换链等）可作为后续单独任务，本次先保证新增资源不泄漏。

## 验证方式

我这边**无法编译**（build 目录绑定在 `C:\共享文件夹\VulkanTest`，此环境只能访问 `\\legion\共享文件夹\VulkanTest`，CMake 会因源目录不存在而拒绝），需在 CLion 中执行：

1. 重新 Build（若报 CMake 配置错误，删除 `cmake-build-release-visual-studio` 重新生成）。
2. 打开 `shaders/TestShader.shader`，先删掉手写的 `[[vk::location(n)]]` 行。
3. 运行程序 → `材质 Importer` 面板点 `+` 导入该 .shader 并点 `应用` → `Model` 面板 `+` 导入一个模型（obj/fbx）。
4. 预期：
   - 控制台出现 `顶点编译成功` / `片段编译成功`。
   - 模型按相机 view/projection 渲染出来（默认相机在原点，可能需在 Hierarchy 面板把相机位置/朝向调到能看见模型）。
   - 未赋材质的 SubMesh 不绘制、不报错（验证"shader 为空跳过"）。
5. 若黑屏：检查 Validation Layer 输出，常见原因是顶点输入 `format` 与 `offset` 不匹配（`inputDescriptions` 来自着色器语义，需与 `Other1::Vertex` 实际布局一致）、或 `VkShaderModuleCreateInfo.codeSize` 不是 4 的倍数。

● Vulkan 实例（Instance）是对 Vulkan 上下文的引用。
● 它定义了 Vulkan 版本以及可用能力。
● 所有 Vulkan 应用都以创建 Vulkan 实例作为起点。
● 实例会枚举所有可访问的物理设备（Physical Device），开发者从中选择一个或多个……
● 随后通过实例创建逻辑设备（Logical Device），由逻辑设备处理后续所有工作！
● 在此之后，实例本身很少再被用到。

● Vulkan 区分两种设备：
-物理设备（Physical Device）
-逻辑设备（Logical Device）
● 物理设备：即 GPU 硬件本身。它拥有内存与用于处理管线的队列，但无法直接与之交互。
● 逻辑设备：物理设备的操作接口。我们会大量使用它。
● 通过逻辑设备，我们在 GPU 上完成所有资源配置。

● 物理设备是对 GPU 硬件本身的引用。
-它包含两个重要组成部分：
-内存：当我们要为资源分配内存时，必须通过物理设备来处理。
● 队列：按先进先出（FIFO）顺序处理提交给 GPU 的指令。不同队列可用于执行不同类型的指令。
● 物理设备是获取得到的，不像大多数 Vulkan 对象那样由我们主动创建（无法凭空创建一个物理设备！）。
● 做法是枚举所有可用设备，再从中挑选合适的。
● 我们现在简单介绍队列，内存部分留到后面课程讲解。

● 物理设备可以拥有多种类型的队列。
● 队列的类型被称为队列族（Queue Families）。
● 一个队列族内部可以包含多条队列。
● 队列族示例：
-图形队列族：用于处理图形渲染指令
-计算队列族：用于执行计算着色器（通用计算指令）
-传输队列族：用于处理数据传输操作
● 队列族可以（而且经常）同时兼具以上多种能力！
● 在枚举物理设备时，我们需要检查该设备是否具备应用所需的队列族。

● 它充当物理设备的操作接口。
● 大量 Vulkan 函数都会用到它的句柄。
● 绝大多数 Vulkan 对象都在设备上创建，我们通过逻辑设备的引用，来指定在哪台设备上创建这些对象。
● 逻辑设备的创建流程相对简单：
-定义要从物理设备分配给逻辑设备的队列族以及队列数量。
-定义所有需要启用的设备特性（例如几何着色器、各向异性过滤、宽线等）。
-定义设备要启用的扩展。
● 过去还需要在此处定义验证层。自 Vulkan 1.1 起，该做法已废弃。

● 默认情况下，Vulkan 本身并不认识 “窗口” 这个概念。
● 这也合理，因为 Vulkan 是跨平台的，不同操作系统的窗口定义各不相同。
● Vulkan 通过扩展来新增窗口相关功能。
● 这类扩展使用极其普遍，所以它们本身就随 Vulkan 一起打包提供！
● 我们可以手动选择需要的扩展…… 不过 GLFW 库提供了接口，可以帮我们自动选择。

● GLFW 全称是图形库框架（Graphics Library Framework）。
● 最初为 OpenGL 设计，后续更新以支持 Vulkan。
● 它支持跨平台窗口创建，并能自动对接 OpenGL / Vulkan。
● 库中提供函数，可识别宿主系统所需的 Vulkan 扩展，并返回扩展列表：
● glfwGetRequiredInstanceExtensions(...)
● 随后我们就可以使用该列表，为 Vulkan 配置正确的扩展

● 默认情况下，Vulkan 不会校验代码。遇到致命错误时不会报错，只会直接崩溃。
● 这么做是为了避免发布版代码中产生不必要的错误检查开销。
● 必须启用验证层（Validation Layer）才能进行校验。
● 每个 “层” 可以校验不同的功能。
- 例如：VK_LAYER_LUNARG_swapchain 用于校验交换链相关功能；VK_LAYER_LUNARG_standard_validation 是常用的全套综合验证层。
● 验证层和扩展类似，不属于 Vulkan 核心内置代码。需要从第三方获取（不过我们将要安装的 Vulkan SDK 已经自带部分验证层）。
● 另外，验证错误的上报功能也不是 Vulkan 核心能力，需要额外启用一个扩展。
● 注意：Vulkan 1.1 之前，实例和逻辑设备可以分别指定验证层。现在不再支持这种方式，实例上配置的验证层会同时覆盖两者。


● Vulkan 应用程序的起点是创建 Vulkan 实例，该实例用于定义这个 Vulkan 应用。
● 枚举物理设备，从中挑选合适的 GPU。
● 创建逻辑设备，用来对接选中的物理设备。
● 物理设备上的多种队列类型（队列族）可以分配给逻辑设备。每种队列负责处理不同类型的指令。
● 可以启用扩展，例如用于将画面输出到窗口的扩展。
● 我们将使用 GLFW 创建窗口，并自动选择对应的扩展。
● 验证层为可选组件，用于在运行时校验代码。发布版本可以关闭验证层，以此降低性能开销。
